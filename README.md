# Плагины задач Sirius Gate

Здесь лежат плагины: новые типы задач, которые подключаются к платформе Sirius Gate
без изменения её кода. Один плагин — одна папка с файлом `task.py`.

| Плагин | Что делает участник |
|---|---|
| `lattice_paths` | считает пути фишки на клетчатом поле с запрещёнными клетками |
| `lights_out` | гасит лампы на поле, где нажатие переключает клетку и её соседей |

## Где писать плагин

Проще всего в редакторе задач на платформе, по адресу `/editor`. Слева код, справа
задача такой, какой её увидит участник. Устанавливать ничего не нужно: код
исполняется в вашем браузере.

- «Запустить» (или Ctrl+Enter в поле кода) пересоздаёт задачу из текущего кода.
- «Другой вариант» показывает задачу с другим номером варианта.
- «Проверить» запускает автоматическую проверку плагина.
- «Скачать» сохраняет файл, «Открыть файл» загружает его обратно.

Если в коде ошибка, над задачей появляется её текст с номером строки.

## Самый короткий плагин

```python
from sirius_gate import EASY, HARD, MEDIUM, Plugin, TaskType, answers, blocks

LIMITS = {EASY: 20, MEDIUM: 200, HARD: 2000}


def generate(level, rng):
    limit = LIMITS[level]
    return {"a": rng.randint(limit // 10, limit), "b": rng.randint(limit // 10, limit)}


def validate(variant):
    return variant["a"] != variant["b"]


def view(variant):
    return blocks.scene(f"Сколько будет {variant['a']} + {variant['b']}?", [], response_hint="/answer <число>")


def check(answer, variant):
    return answers.integer(answer) == variant["a"] + variant["b"]


def solution(variant):
    return f"/answer {variant['a'] + variant['b']}"


PLUGIN = Plugin(
    name="two_numbers",
    version="1.0",
    author="Команда 7",
    description="Сумма двух чисел.",
    task_types=[
        TaskType(
            key="two_numbers",
            title="Сумма двух чисел",
            generate=generate,
            validate=validate,
            check=check,
            view=view,
            solution=solution,
        )
    ],
)
```

## Из чего состоит плагин

`Plugin` описывает плагин целиком: имя, версию, автора, описание и список типов задач.

`TaskType` описывает один тип задачи. У него пять частей.

| Часть | Что делает |
|---|---|
| `generate(level, rng)` | создаёт вариант задачи для уровня сложности. Вариант — это словарь со всем, что определяет задачу |
| `validate(variant)` | отвечает `True` или `False`: годится ли вариант. Негодные варианты платформа отбрасывает и создаёт новые |
| `check(answer, variant)` | отвечает `True` или `False`: верен ли ответ участника |
| `view(variant)` | возвращает сцену из блоков. Это всё, что видит участник |
| `model_context(scene)` | необязательная часть: что рассказать языковой модели о задаче |

Ещё две необязательные части:

- `solution(variant)` возвращает эталонный ответ. По нему работает автоматическая
  проверка, поэтому лучше его написать.
- `move(variant, text)` делает задачу интерактивной, см. ниже.

Уровней сложности три: `EASY` (простой), `MEDIUM` (средний) и `HARD` (повышенной
сложности).

## Четыре правила

1. **Случайность только из `rng`.** Тогда один и тот же номер варианта всегда даёт
   одну и ту же задачу. Платформа проверяет это при загрузке плагина.
2. **Вариант — это словарь из чисел, строк, списков и словарей.** Платформа хранит
   его в формате JSON. Множества и кортежи в нём не сохранятся.
3. **Участник видит только то, что вернула `view`.** Ответ в сцену попадать не
   должен. Языковая модель тоже получает только сцену и никогда не видит вариант.
4. **Изменилась задача — меняется версия.** Если плагин стал создавать или проверять
   задачи иначе, увеличьте `version`. В плагине можно использовать только
   стандартную библиотеку Python и пакет `sirius_gate`.

## Из чего собирается сцена

```python
from sirius_gate import blocks
```

| Блок | Что показывает |
|---|---|
| `blocks.text("...")` | абзац текста |
| `blocks.table(столбцы, строки)` | таблицу |
| `blocks.grid(клетки)` | клетчатое поле |
| `blocks.cell("3", tone="accent", command="/op press:0:1")` | клетку поля, с командой она становится кнопкой |
| `blocks.buttons([blocks.button("Сбросить", "/reset")])` | ряд кнопок |
| `blocks.facts("Ходов: 3", "Лимит: 10")` | короткие строки состояния |

Оттенки клетки: `plain`, `accent`, `muted`, `good`, `bad`.

Сама сцена собирается так:

```python
blocks.scene(
    "Текст условия",
    [blocks.grid(...), blocks.facts(...)],
    commands=["done"],                    # задача завершается словом done
    help_lines=["/op press:1:2 — нажать клетку"],
    response_hint="/answer <число>",      # формат ответа в поле ввода
    answer_guide="Напишите число путей.",  # фраза под условием о том, как отвечать
)
```

## Интерактивная задача

Участник может менять задачу командой `/op <что-то>` или кликом по клетке или кнопке,
у которой задана такая команда. Для этого в `TaskType` добавляется `move`:

```python
def move(variant, text):
    if text != "plus":
        raise Rejected("Можно только прибавлять.")
    variant["count"] += 1
    return variant, "Прибавили один."
```

`move` получает текущий вариант и текст хода. Она возвращает изменённый вариант, при
желании вместе с сообщением участнику. Чтобы отклонить ход, вызовите `Rejected` с
объяснением. Команды `/undo` и `/reset` после этого работают сами, писать их не нужно.

Если ответ пока нельзя засчитать, `check` вызывает `NotYet` с подсказкой. Задача
остаётся открытой:

```python
def check(answer, variant):
    if any(map(any, variant["lamps"])):
        raise NotYet("Ещё не все лампы погашены.")
    return True
```

Полный пример — `lights_out/task.py`.

## Языковая модель

Участник может обращаться к модели во время решения. Плагин с моделью не общается:
это делает платформа. Модель получает только сцену, то есть то же, что видит участник.

Если сцена содержит лишнее для модели, плагин задаёт `model_context(scene)` и
возвращает из неё словарь с тем, что модели стоит знать. Вариант задачи в эту функцию
не передаётся.

## Автоматическая проверка

В редакторе это кнопка «Проверить». Из терминала:

```bash
cd sirius_test/backend
.venv/bin/python -m sirius_gate.check /путь/к/sirius_gate_modules lights_out
```

Проверка создаёт по 40 вариантов на каждом уровне и печатает таблицу:

```text
lights_out (Выключи свет), версия lights_out-1.0
  сложность             создано  разных  эталон принят  самый частый ответ  дольше всего
  простой                40/40     34        40/40              —                 0 мс
  средний                40/40     40        40/40              —                 0 мс
  повышенной сложности   40/40     40        40/40              —                 0 мс
```

- **создано** — сколько вариантов получилось без ошибок;
- **разных** — сколько среди них различных задач. Если их мало, участники получат одинаковые варианты;
- **эталон принят** — засчитывается ли решение из `solution`;
- **самый частый ответ** — в какой доле вариантов подошёл бы один и тот же ответ. Чем больше число, тем проще угадать;
- **дольше всего** — самое долгое создание варианта.

Проверка также убеждается, что пустой ответ не засчитывается. Если разных задач
меньше половины или один ответ подходит более чем к половине задач, под строкой
уровня появляется замечание.

## Как плагин попадает на платформу

Платформа читает плагины из папки, указанной в переменной `TASK_MODULES_DIR`:

```bash
cd sirius_test/backend
TASK_MODULES_DIR=/путь/к/sirius_gate_modules .venv/bin/uvicorn app.main:app --reload --port 8001
```

После запуска типы задач из плагинов появляются в конструкторе контеста с пометкой
«модуль» и именем автора. Если плагин не загрузился, конструктор показывает его имя и
причину. Остальные задачи при этом продолжают работать.

Организатор может открыть любую задачу без контеста в разделе «Песочница» своей
панели. Кнопка «Перечитать модули» подхватывает изменённый файл без перезапуска
сервера.
